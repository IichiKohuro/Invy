# 0004. Обновление Desktop: Velopack + фид на сервере Invy

**Статус:** Принято с оговорками (спайк фазы 0, 2026-11-04) — установка и обновление на Windows проверяются вручную, см. [чек-лист](../spikes/phase-0/checklist.md)

## Контекст

Desktop должен сам находить новую версию в домашней сети и обновляться одним действием. Интернет и облачные хранилища не используются: релизы раздаёт сервер Invy.

## Решение

1. **Velopack 1.2** (`Velopack` в приложении, `vpk` — локальный инструмент репозитория в `dotnet-tools.json`).
2. **Фид раздаёт сервер:** `GET /updates/{платформа}/*` из `{DataPath}/releases/{платформа}` (`UpdateFeed.cs`):
   - только известные типы файлов (`.json`, `.nupkg`, `.exe`, `.zip`, `.apk`, `.md`), выход за пределы каталога невозможен;
   - `Cache-Control: no-cache` для манифестов, `Setup.exe` и `Portable.zip` (имя не меняется между версиями), `immutable` — для пакетов с версией в имени (`*.nupkg`, `*.apk`).
3. **Клиент** (`DesktopUpdateService`): `VelopackApp.Build().Run()` — первая строка `Main`; `UpdateManager` + `SimpleWebSource("http://сервер:5470/updates/win/")`; проверка через 30 с после старта и из меню трея; пакет скачивается в фоне; установка — «Установить X и перезапустить» в трее или автоматически после выхода (`WaitExitThenApplyUpdates`).
4. **Упаковка** — `tools/pack-desktop.ps1 -Version X`: `dotnet publish` (self-contained, ReadyToRun на Windows) → `vpk pack --runtime win-x64` → каталог релизов сервера. Velopack сам строит дельту от предыдущей версии в каталоге.

## Проверка

| Что | Как | Результат |
|-----|-----|-----------|
| Кросс-упаковка Windows-релиза на Linux (`vpk [win] pack`) | Два релиза подряд | ✅ Setup.exe, Portable.zip, full/delta-пакеты; дельта 0.1.0 → 0.2.0 — **30 КБ** против 15 МБ полного пакета |
| Сервер отдаёт фид настоящему клиенту Velopack | Живой dev-сервер + `SimpleWebSource`; автотест `UpdateFeedTests` | ✅ фид прочитан, дельта скачана, SHA-256 совпал |
| MIME-типы, кэширование, запрет обхода каталога | `UpdateFeedTests` | ✅ |
| `tools/pack-desktop.ps1` | PowerShell 7.6 на Linux, упаковка 0.3.0 поверх 0.2.0 | ✅ дельта построена автоматически |
| Установка `Setup.exe`, обновление с перезапуском, установка при выходе | — | ⏳ вручную на Windows |

## Последствия

- Self-contained: `Setup.exe` ≈ 56 МБ, полный пакет ≈ 49 МБ; обновления между версиями — дельты (обычно десятки КБ – единицы МБ).
- Без сертификата подписи кода Windows SmartScreen предупредит при первом запуске `Setup.exe`; обновления через Velopack идут без предупреждений.
- Velopack обновляет только установленное приложение: при запуске из `bin/` пункт меню сообщает «только в установленной версии».
- Наследуемый файл `RELEASES` (формат Squirrel) сервер не отдаёт — Velopack 1.x использует `releases.{channel}.json`.
- Адрес сервера в фазе 0 берётся из `INVY_SERVER` (по умолчанию `http://localhost:5470`); с фазы 2 — из настроек подключения и автообнаружения. Публикация релиза на сервер по сети и событие `UpdateAvailable` — фаза 8.
